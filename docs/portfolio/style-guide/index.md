# Documentation Style Guide

The Documentation Style Guide defines the standards for creating clear, consistent, and user-focused technical documentation.

It establishes writing conventions, formatting guidelines, terminology, and editorial practices to ensure documentation remains accurate, maintainable, and easy to use.

## Who should use this guide?

This guide is intended for:

- Technical writers
- Software engineers who contribute documentation
- Product managers
- Subject matter experts
- Documentation reviewers

## At a glance

This guide covers:

- Writing principles
- Voice and tone
- Terminology
- Procedures
- Formatting
- Accessibility
- Docs-as-Code practices
- Editorial review

## Documentation philosophy

Good documentation helps users accomplish tasks—not simply learn about features.

When writing documentation:

- Write for the intended audience.
- Focus on user goals rather than product features.
- Explain concepts only when they help users complete a task.
- Keep information modular and reusable.
- Write once and link to related topics instead of duplicating content.
