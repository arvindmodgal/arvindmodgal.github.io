# Writing principles

Good documentation helps users accomplish their goals quickly and confidently. These principles provide the foundation for creating documentation that is clear, consistent, and easy to maintain.

Apply these principles to every document, regardless of its audience or format.

## Write for your audience

Write for the people who will use the documentation, not for the people who built the product.

Consider the reader's:

- Technical knowledge
- Goals
- Context
- Experience level

Explain unfamiliar concepts only when they help the reader complete a task.

!!! example "Example"

    Instead of explaining how firmware analysis works, explain how to upload firmware and interpret the assessment results.

---

## Focus on user tasks

Organize documentation around the tasks users want to accomplish rather than around product features.

Users visit documentation to answer questions such as:

- How do I create a device?
- How do I upload firmware?
- How do I reset my password?

Avoid organizing documentation using the application's menu structure or feature list.

---

## One idea per paragraph

Keep paragraphs short and focused.

Each paragraph should communicate a single idea. If a paragraph introduces a second idea, split it into two paragraphs.

Short paragraphs improve readability, especially on mobile devices.

---

## Keep concepts and procedures separate

Different types of information serve different purposes.

Use:

- **Concept** topics to explain ideas.
- **Procedure** topics to describe how to perform a task.
- **Reference** topics to provide factual information.

Avoid mixing conceptual explanations into procedural steps unless they are necessary to complete the task.

---

## Write once and link

Avoid duplicating information across multiple pages.

Instead of repeating instructions, link to the existing topic.

This approach:

- Reduces maintenance effort.
- Prevents inconsistencies.
- Keeps documentation concise.

---

## Use progressive disclosure

Present only the information users need at each stage of a task.

Start with the essential steps.

Provide additional details through notes, links, or related topics instead of interrupting the primary workflow.

---

## Be consistent

Use consistent terminology, formatting, and page structure throughout the documentation.

Consistency helps readers learn the documentation and locate information more quickly.
